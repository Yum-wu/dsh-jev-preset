# 20–80% 难度带题集 —— 造题契约(2026-10-15)

## 一、为什么造这批题

本仓现有题池两极分化,**测不出任何方法的差异**:

| 题池 | C0 基线正确率(standard 预设,单次直答) | 问题 |
|---|---|---|
| 常规 numeric(40 题) | **97.5%** | 天花板,没有提升空间 |
| `trap_candy`(30 题) | **0%** | 地板,所有方法都 0 分 |

⇒ 需要一批 **C0 基线落在 20%~80%** 的题,才能测出 JEV / 外部验证指令 / 多路采样 的净效应。

## 二、难度来源(唯一许可的旋钮)

**在题干里放 1 个「读得到、但容易漏读」的限定。** 不要 0 个,不要 3 个以上。

- 0 个限定 ⇒ 97.5% 天花板(现有 numeric 就是这样)
- 5 个限定 ⇒ 0% 地板(现有 `trap_candy` 就是这样)
- **1 个限定 ⇒ 期望落进 20%~80%**

⚠ 允许的难度来源**只有两类**:
1. **信息提取** —— 限定写在从句/括号/长句里,读了就一定对,漏读就一定错。
2. **单步口径选择** —— 二选一的约定(开区间 vs 闭区间、向上 vs 向下取整、先舍 vs 后舍)。

**禁止**靠「需要长链推理才能做对」制造难度 —— 那测的是推理力,不是我们要测的东西。

## 三、硬约束(违反即废题)

1. **唯一数值答案**,可程序化判分。
2. 题面**自包含**:不得依赖网络、外部文件、实时行情。所有输入数字写进题面。
3. 题面用**中文**。
4. 题末必须带作答格式块,**与现有题集逐字同构**(注意:是三个反引号包住的 json 块):

   ```
   【作答格式(判分程序只读这一段)】
   回复最后必须给出一个 ```json 代码块,内容为单个 JSON 对象,键名严格如下:
   {"<键名>": "<值>"}
   所有数值一律写成字符串(如 "123.45"),按题目要求的精度与舍入,不要带单位或千分位。
   ```

5. 每题的 `expected` **必须由独立 solver 脚本复算得出**,**不得手写**。
6. 不得与现有题集重复 —— **改数字不算新题**,必须换陷阱类型或换场景。

## 四、输出(每批次两个文件,放同一目录)

### 1) `<name>.jsonl` —— 每行一个 JSON 对象,单行不换行

```json
{"id":"<category>-20261015-<NN>","category":"<category>","kind":"numeric","question":"<题面,含作答格式块>","expected":{"<键名>":"<值>"},"suite_version":1,"seed":20261015}
```

- `id` 形如 `<category>-20261015-00` … `-14`(两位数,从 00 起)
- 题面里的换行写成 `\n`

### 2) `solvers_<category>.py` —— 独立复算脚本

- 读同目录 `<name>.jsonl`
- 对每题**从题面文字独立重算**(**不要**直接读 `expected` 当答案)
- 逐题打印 `OK <id> <值>` 或 `MISMATCH <id> expected=<e> solver=<s>`
- 退出码:全部 OK = `0`;有 MISMATCH = `1`

## 五、必交证据

真跑 `python solvers_<category>.py`,**贴出原始 stdout 与退出码**。
不贴 = 未完成。solver 与 expected 必须全部一致才可交付。
