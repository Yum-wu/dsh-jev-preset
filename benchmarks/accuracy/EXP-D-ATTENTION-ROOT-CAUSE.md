# 实验 D:根因定性 —— 审题失败是"注意力问题",不是"推理能力问题"

**日期**:2026-09-28
**问题**:糖果题的普遍失败,是模型**不会做**(推理能力)还是**没看题**(注意力)?
**设计**:同一道题两个版本,唯一差异是关键条件的呈现方式。

---

## ⚠️ 前置更正:本轮实验中的伪重复错误

在报告结论前,必须先记录一个**已发现的实验设计错误**:

我最初把 `combo/ds-flash` 与 `workbuddy2api/cn:hy4-preview` 当作**两个独立模型**,
据此得出"5 个模型里 4 个盲目 → 跨模型普遍盲区"的结论。

**该结论错误。** 经查 `~/.opencodex/config.json`:

```json
"combos": {
  "ds-flash": {
    "strategy": "round-robin",
    "targets": [
      { "provider": "workbuddy2api", "model": "global:deepseek-v4.1-flash", "weight": 4 },
      { "provider": "workbuddy2api", "model": "global:hy4-preview-f",       "weight": 2 },
      { "provider": "workbuddy2api", "model": "cn:hy4-preview",             "weight": 2 },
      { "provider": "workbuddy2api", "model": "cn:deepseek-v4.1-flash",     "weight": 1 }
    ]
  }
}
```

**`combo/ds-flash` 是 `workbuddy2api` 的 round-robin 组合路由**,其 4 个目标全部来自
`workbuddy2api`,其中包括我当作"独立样本"的 `cn:hy4-preview`。

**这是统计学上的伪重复(pseudoreplication)**:把同一来源的样本计为多个独立观测,
会人为放大样本量、低估方差,从而得出过强的结论。

**更正**:实际独立模型只有 **3 个**(shangtang / opencode-zen / google-antigravity),
不是 5 个。原"4/5 模型盲目"应更正为 **"2/3 独立模型盲目"**。

**影响范围**:
- ❌ 作废:"跨模型普遍盲区"(基于伪重复计数)
- ✅ 保留:`gemini 100% vs ds-flash 11%`(两者真独立)
- ✅ 保留:**实验 D 的结论**(同模型自身前后对照,不依赖跨模型计数)

## 一、实验设计

原题的关键条件**藏在括号里**:

> 每种糖果有两种不同的形状(圆形和五角星形,**不同的形状靠手感可以分辨**)。

变体(强调版)把它提为独立段落并显式要求利用:

> 每种糖果有两种不同的形状:圆形和五角星形。
> **【重要条件,请务必利用】不同的形状靠手感可以分辨**,也就是说你在摸的时候
> 能够自主选择摸圆形还是五角星形,因此你可以自己决定取多少个圆形、多少个五角星形。

**除此之外题目完全相同**(同 9 道参数化变体,同期望答案,同判分)。

## 三、结论:**这是注意力问题,不是能力问题**

```
仅改变关键条件的呈现方式(括号 → 独立段落 + "请务必利用"):
  ds-flash:      11.1% → 100%   (+88.9pp)
  shangtang:     盲目  → 100%
  space-bunny:   盲目  → 100%
  (gemini 原本已 100%)
```

**同一个模型、同一道题、同一个期望答案。** 唯一变量是"条件写得够不够显眼"。

**推论**:
1. 模型**具备**解题所需的全部推理能力(强调后 4/4 模型均 9/9)
2. 失败发生在**信息提取阶段**,不在推理阶段
3. 与 CRT 的经典解释一致:system 1 快速扫读 → 漏掉括号内容 → 给出直觉答案
4. **跨 3 个独立 provider 一致** → 该结论不依赖单一模型

## 四、对 JEV 设计的重大影响

### 4.1 三种解法的成本效益

| 方案 | 效果 | 成本倍数 |
|---|---|---|
| 加路数(C3 三路) | 11.1% → 44.4%(+33pp,**不显著** p=0.25) | **×18.7** |
| 换模型(gemini) | 11.1% → 100% | ×5.4 |
| **改提示(强调关键条件)** | **11.1% → 100%** | **≈ ×1** |

**提示工程的性价比远高于换模型,更远高于加路数。**

### 4.2 JEV 应有"题干结构化"前置步骤

当前 JEV persona 要求三路隔离采样,但**没有**要求主会话先做**题干结构化**
(提取关键条件、显式化隐含前提)。本实验证明这一步价值最大。

**建议新增纪律**:派发三路**之前**,主会话必须先输出一份
「题干关键条件清单」,并把该清单**写入每一路的 prompt**。

逻辑:
- 若关键条件被漏掉 → 三路都漏(共享盲区,加路数无用)
- 若主会话已提取 → 三路都拿到完整条件,盲区消除

### 4.3 "三路一致"的更精确解释

之前观察到 ds-flash 三路在 5/9 题上收敛到同一错值,我归因为"共享推理盲区"。
现在有更精确的解释:**三路都漏读了同一句话**。
不是"共享推理错误",而是**共享信息提取失败**。
