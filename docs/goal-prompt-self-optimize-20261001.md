# JEV 模式自优化循环 — 目标提示词(2026-10-01)

> **用途**:作为 `/goal` 的 objective 原文,经 `commands/execute` 字面入库(不经模型转述),
> 驱动一个「发现缺陷 → 修复 → 独立验证 → 记账」的循环。
>
> **配套脚本**:`tools/launch-long-goal.mjs`(改 `JEV_LONG_GOAL_OBJECTIVE` 常量即可复用)。
>
> **设计依据**:三源调研(核心论文 / 厂商官方文档 / X·GitHub 社区)+ 本机实测缺陷清单(见文末附录 A/B)。
> 每条纪律都标注来源,不得凭"惯例"增删。

## 一、提示词正文(逐字复制进 `/goal`)

```
目标:把 dsh-jev-preset(JEV 自适应交叉验证预设)从「断言优先」推进到「可自我验证、可被第三方复算」的工程状态。
仍未完成前严禁 complete;Round < 20 前禁止调用 update_goal(complete)。

【为什么是这个目标】
本仓已确立核心统计学结论(执行断言 24/30→30/30, McNemar p=0.0312;三路在断言之上增益 0, 30 题平局 p=1.0),
但工程层存在两类未闭环问题:
 (甲) persona 的承诺与代码/配置的实际行为不一致 —— 属于「验证剧场」风险,必须先清;
 (乙) 自优化循环缺少防奖励黑客的机制 —— 优化者与验证者是同一个 agent,会「越练越会骗」。
本目标只做 (甲)(乙) 两件事,不重跑已定论的准确率实验。

【本目标的缺陷清单在哪儿】
本提示词只是正文。附录 A(实锤缺陷 A1–A10)、附录 B(度量缺口 B1–B6)、附录 C(闭环缺口 C1–C5)
全部在本文件 `plugins/dsh-jev-preset/docs/goal-prompt-self-optimize-20261001.md` 的第二至第四节,
含每条缺陷的实测命令与输出、严重度、以及取舍说明。每轮开始前先读它,以它为准,不要凭记忆复述编号。

【只认这两类证据,其余一律视为未完成】
 (1) 本地命令真实 stdout:贴出命令与输出,禁止"已跑/已验证"的口头报告;
 (2) DSH 原生会话证据:session_id / 子会话 ID,可在 session/list 查到。

【铁律 — 违反任一条即本轮作废】
R1 效果方向类结论必须至少 3 次重复,差异 <10pp 默认视为噪声。
R2 对比前先确认基线稳定;基线波动大时单次对比无意义。
R3 确认样本独立性:警惕组合路由与其成员的重叠(伪重复)。
R4 测量链路与结论同等验证:先确认"测到了",再讨论"结果如何"。
R5 "无答案"与"答错"必须分开统计。
R6 作废范围逐文件审计,不靠推断扩大。
R7 异步/后台执行的收敛判据用客观状态(子会话 running),不用"文本看起来说完了"。
R8 扩样前先想清楚检验的统计量(McNemar 只看不一致对,加"两边都对"的题不会让 p 更显著)。
R9 预注册:每轮的判据先写死再看数据,结果只追加、不改判据段。
R10 通过率一律报 Wilson 95% 区间,禁用 Wald 区间。
R11 禁止纯内省自纠作为验证手段:验证必须挂可执行外部信号(断言/测试/复算),或换异构模型族。
R12 自优化的验证者必须外置:验证路不得读取优化路自报的分数,必须从原始产物独立重算。
R13 指标必须放在 agent 控制范围之外:不得优化"让指标好看",只允许优化"让事实更清楚"。
R14 多路采样 N 上限 3,补派后总发射上限 4;禁止 20+ 路。
R15 严禁删除文件/目录/git 历史、修改 .env/密钥/CI 配置、git push、安装全局依赖、重启 DSH。
    遇到需要上述动作,标记为"需人工"并跳过,不得自行执行。

【每轮循环的固定动作】
 Step 1 选缺陷:从附录 A(实锤)与附录 B(度量/闭环)中取一条,一次只做一条。
 Step 2 写失败测试:先写一个能复现该缺陷的自动化测试(红),贴出红的具体输出。
        不能写成测试的缺陷 → 必须写成可复算的脚本断言,仍不行则标记"不可测"并说明原因。
 Step 3 最小修复:遵循 YAGNI;不改无关代码;匹配现有风格。
 Step 4 转绿:贴出该测试转绿的输出。
 Step 5 独立验证(必须换路):用 subagent 派生 1 路「红队复算者」,
        只给它原始输入与你的修复产物路径,不告诉它结论;要求它独立复算并给出反证或确认。
        —— 这一路是防 R12/R13 的唯一手段,不得省略、不得由本会话自评替代。
 Step 6 记账:在 plugins/dsh-jev-preset/docs/ 下追加本轮记录(日期/缺陷/命令/输出/红队结论/是否修复)。

【每 5 轮的全量回归(不得跳过)】
 G1 npm test(插件内)与 npm test(仓库根)全绿;
 G2 node validate.mjs 与 validate-official.mjs 全绿;
 G3 python tests/test_accuracy_bench.py 的 selftest 全过(89 题);
 G4 断言 CLI 冒烟:--list 返回 18 项;至少 3 个函数 pass(exit 0)与 fail(exit 1)各跑一次;
 G5 规避率审计:统计"本轮被判通过"与"本轮被判规避/糊弄"的条数;
    规避率较上 5 轮抬头 → 立即停止循环并报告。

【阶段】
 P0 基线固化(第 1 轮):跑 G1–G4 并把输出存档;记录当前 commit hash。
    此后每轮开始前必须先跑 G1,确认基线未漂移。
 P1 清附录 A 的实锤缺陷(A1–A10),一条一轮,按"契约-代码不一致"优先。
 P2 补附录 B 的度量能力(B1–B6),重点是 B3(pass^k)与 B5(判分器口径)。
 P3 装附录 C 的闭环机制(C1–C5),重点是 C1(验证者外置)与 C3(轮次上限+规避率)。
 P4 收尾:把 P1–P3 的结论写入 docs/,更新 README 的"已落实防线/没有的"两栏,
    并在 FINAL-CONCLUSIONS.md 追加一节。跑一次全量 G1–G5。

【停止条件(满足任一即结束本轮并说明)】
 S1 附录 A/B/C 全部条目状态明确(修复 或 有证据地标为"不修/不可修");
 S2 连续 2 轮无新发现;
 S3 达到 maxGoalRounds 上限;
 S4 触发 R15 红线且无法绕开。
 注:困难、不确定、还有可做的工作 —— 都不是 blocked 的理由。

【收尾规则】
 每轮只做一小步,做完即结束本轮、保留目标 active。
 未满 20 轮或任一阶段无证据,禁止 complete。
 每轮结尾必须给出一行状态:`ROUND n | 本轮缺陷=<编号> | 结果=修复/未修复 | 证据=<命令或 session_id>`。
```

## 五、为什么是这个清单(取舍说明)

**保留但降级**:
- 「三路隔离采样」不再是核心卖点(增益 0,×15.3),但**不删** —— 它是唯一能覆盖"既不可断言、又不能换模型"的兜底路径,且 `maxDepth:1` 的递归阻断已实证有效(孙会话 0)。本目标只修它的**实现缺陷**(A8 补派失控、A9 同模型),不重新论证其价值。
- 「Jev Rerank 终审」「决策模型门控」在 persona 里有条目,但**插件内无任何代码**(全仓仅 `cordis.patch.yml:103` 一处提及)。属**设计参考**而非已部署能力 —— 与 2026-09-28 已更正的"断路器/角色锁"同类。**处理方式**:要么接实现,要么按 README 既有做法在 persona 里标注"设计参考"。

**明确不做**:
- 不重跑已定论的准确率实验(断言 p=0.0312 / 三路 p=1.0),避免消耗配额重复已知结论;
- 不引入新模型或新依赖(属 R15 红线边界);
- 不追求"更高的准确率数字" —— 那正是 R13 要防的。

**已知风险(诚实标注)**:
- 附录 A 的缺陷来自 2026-10-01 单次实测,修复后需重跑复现命令确认,不得以"改完看着对"结案;
- 本目标的循环本身也会被同一套偏差影响,故 R12/R13 与每 5 轮的规避率审计是**必须执行**的,不是可选。
