## 一、一句话结论

> ⚠️ **本句原为「JEV 三路能防随机错误,防不住系统性盲区」—— 两半都需要修正(2026-09-30)。**
>
> | 半句 | 状态 | 依据 |
> |---|---|---|
> | "能防随机错误" | ⚠️ **仍未直接验证** | 本仓**没构造过随机错误实验**;但 `EXP-F` 从侧面证明:**执行断言**对随机计算错误有效(24/30→30/30, p=0.0312),而三路对同样这批题**增益为 0**(`EXP-G`) |
> | "改善信息提取(盲目率 100%→33%)" | ❌ **已证伪(仅指 30 题批)** | 33% 是测量伪影:30 题批 18 条"无答案"被算成"非盲目"撑大分母。真实 **83.3%**。**9 题批无此问题** |
>
> **修正后的准确表述**:
> **JEV 的价值在「执行断言」,不在「三路采样」。** 三路在可断言的题上完全多余
> (30 题逐题平局, p=1.0, 成本 ×15.3);在审题类缺陷上无显著增益(9 题 p=0.25, 30 题错答全属漏读型)。
>
> **已全部测完(2026-09-30)**,不再"未测":
> - **执行断言对可跑断言的题有效且显著**:30 题 24/30 → 30/30,p=0.0312,成本 ×2.0(`EXP-F`)
> - **三路在断言之上增益为 0**:30 题完全平局 p=1.0,成本 ×15.3(`EXP-G`)
> - 三路在 candy 上:9 题 11.1%→44.4%(p=0.25 不显著),错答全属漏读型

## 二、边界总表

> ✅ 本表已按 2026-09-30 实测更新。**9 题批数字有效,30 题批数字已作废**
> (区分依据见文件头审计表)。

| 场景 | 三路是否有效 | 实测证据 | 建议 |
|---|---|---|---|
| **数值计算(可写成断言)** | ❌ **完全多余** | 30 题 A2 vs C3F **30/30 vs 30/30, p=1.0**(`EXP-G`) | **单路 + 真跑断言**(×2.0) |
| 数值计算(公式明确, C0 已 97.5%) | ❌ 无增益 | `DIFFICULTY-CALIBRATION.md` | Fast-Pass 直出 |
| 随机性算错/笔误 | ❌ **三路无用,断言有用** | 断言 24/30→30/30 p=0.0312;三路叠加增益 0 | **执行断言** |

| 成本敏感场景 | ✅ **负收益** | 三路 token 为单路 **6–15 倍**(视题) | Fast-Pass |

## 三、关键实测数据(全部来自本仓)

### 3.1 三路 vs 单路:审题陷阱题(9 题批,已审计为可信)

| 配置 | 正确率 | 盲目率 | 成本/题 |
|---|---|---|---|
| ds-flash C1(单路) | 11.1% | 89% | 14 万 |
| ds-flash C3(三路) | 44.4% | 56% | 263 万 |
| **gemini C1(异构单路)** | **100%** | **0%** | 75 万 |

**结论**:换模型 **+89pp / ×5.4 成本**;加路数 **+33pp(p=0.25 不显著)/ ×18.7 成本**。
**换模型在正确率与成本上双双占优。**

> **可信度**:本表来自 `runs-candy.jsonl`(9 题)。经 `_audit_measurement.py` 审计,
> 其 C3 的 9 条**全部出了答案块**,未受 2026-09-30 测量 bug 影响 → **数字有效**。
> (受影响的只是 30 题批 `runs-c30-c3-sb.jsonl`,该批的 3.3% 已作废。)

出处:`CANDY-CROSS-MODEL.md`、`CANDY-C1-VS-C3.md`

### 3.2 天花板效应:常规数值题上三路无空间

首轮 C0(纯推理、禁工具、最弱基线)对 **39/40 = 97.5%**,
难度筛选 `[0.2, 0.8]` → **kept = 0**(无一题有区分力)。

**结论**:常规数值题上 C1/C3 最多比 C0 高 2.5pp,**跑三路是纯浪费**。

出处:`DIFFICULTY-CALIBRATION.md`

### 3.3 同模型多路 = 共享盲区(不是独立验证)

ds-flash 三路在 **5/9** 道陷阱题上各自独立跑,却**收敛到同一错值**(26/27/28/23/20)。

**结论**:这不是随机错误,是所有实例共享的**注意力弱点**。
三路"一致"在此类缺陷上**毫无保护作用** —— 印证行为纠缠研究
([arXiv:2604.07650](https://arxiv.org/abs/2604.07650))。

出处:`CANDY-CROSS-MODEL.md` 第四节

### 3.4 免费档并发 = 必挂(运营边界)

| 配置 | 样本 | 成功 | 限流失败 |
|---|---|---|---|
| 免费档(muse-spark)同模型并发 | 3 | 0 | **3** |
| 付费档(ds-flash)同模型并发 | **9** | **9** | **0** |
| 付费档异构并发 | 2 | 2 | 0 |

**结论**:红线是**档位**,不是"同模型"。免费档并发三路必挂(429 + 6 次重试耗尽,单路烧 ~320s)。

出处:`evidence/p1-route-confound-controlled-2026-09-28.md`

### 3.5 递归阻断有效(结构性边界)

`maxDepth: 1` 端到端实证:孙会话数 = **0**,引擎抛 `SubagentDepthError`。

出处:`evidence/p0-depth-limit.log`

### 3.6 门控行为正确

C3 在 9 道陷阱题中 **8/9** 派发了子代理(`[4,3,3,0,3,3,3,4,3]`),C1 严格 0/9。

**结论**:persona 的路由纪律本身有效(该走三路的确实走了)。

出处:`CANDY-C1-VS-C3.md` 第三节

## 四、决策树(可直接照用,2026-09-30 按实测重排)

```
任务进入
  │
  ├─ 是低危/日常(检索、读取、常规问答、小改)?
  │    └─ 是 → 【Fast-Pass 单次直出】
  │
  ├─ 结论是唯一数值,且能写成可执行断言?
  │    └─ 是 → 【单路作答 + 真跑代码复算】★首选
  │           理由: 30 道计算题实测 24/30 → 30/30 (p=0.0312), 成本仅 ×2.0
  │           · 断言失败 → 不得放行, 先修断言; 修不动再转三路
  │
  ├─ 依赖"读懂题干细节/隐含条件"?
  │    └─ 是 → 【换异构模型 或 题干结构化】
  │           理由: candy 实测三路 p=0.25 无显著增益, 错答 5/5 全是漏读型(bias)
  │           优先结构化(×1) 而非换模型(×5.4)
  │
  ├─ 无法写成断言 且 先验高危(资金取舍/安全/并发/状态机)?
  │    └─ 是 → 【三路隔离采样】(兜底)
  │           · 三路必须异构(优先项)
  │           · 路由档位: 禁止免费档并发
  │           · 执行断言权重 > 三路共识
  │           · ⚠ 已跑断言时再加三路 = 增益 0, 成本 ×10.6
  │
  └─ 其他 → Fast-Pass
```

## 六、未验证 / 待补(明确标注,不推断)

| 项 | 为什么重要 | 验证方法 |
|---|---|---|
| **样本量仅 9 题** | 所有 candy 结论都需 ≥50 题复核 | 扩题后重跑 C1/C3 |
| **仅两个模型** | 不能推广为"gemini 优于 ds-flash" | 加第三个模型(如 opus)对照 |
| **gemini C3 未跑** | 单路已 100%,C3 无空间(有意省略) | 若要验证"三路在弱模型上是否更有效"可跑 |
| **3 题成功机制未核实** | 推测某一路发现提示,未读日志 | dump 子代理日志逐字确认 |
| **三路对"随机错误"的有效性** | 设计目标,但本仓**未构造随机错误实验** | 构造已知易错题,看三路是否捕获分歧 |
| **异构模型间的行为纠缠程度** | 只引用他人度量,本机未测 | 构造同步失败集,算 BEI/CIG |
| **补派上限=1 是否最优** | 保守取值,未做对照 | 1/2/3 次上限对照实验 |
| **`docs/performance-spec.md` 门槛值** | 拍定目标值,无测量依据 | 真实三路实测回填 |

## 七、对 JEV 设计的净影响

| 项 | 改动 |
|---|---|
| 异构路由 | 从"推荐"**升级为"优先项"**(附实测数据) |
| 同模型多路 | 明确其**硬边界**:只防随机错误,防不住系统盲区 |
| Fast-Pass 门槛 | 得到成本数据支持(18.7x,简单题负收益) |
| 执行断言优先 | 得到理论支持(行为纠缠 → 共识≠正确) |
| 补派预算封顶 | 得到 MASFT FC3 支持 |
