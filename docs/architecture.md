# JEV 自适应交叉验证架构设计全景 (Architecture Specification)

## 一、核心设计哲学：JEV (Judgment-Execution-Verification)

JEV 模式旨在彻底解决大语言模型在量化金融推导、资金风控计算、安全边界判定中的三大致命缺陷：
1. **过度自信的虚假自洽**：单会话窗口模型在产生数值计算错误时，往往能给出语法和措辞极其完美的解释；
2. **同上下文自回归污染**：在同一上下文让模型扮演“多个专家”，后文必然被前文的 Token 概率分布所锚定，伪多路毫无独立验证价值；
3. **缺少物理执行真值**：文字推演无法替代沙箱运行，代码未真跑通过不能作为放行依据。

## 三、三路角色矩阵设计 (Perspective Diversity)

| 采样路径 | 角色定义 | 核心职责 | 关注缺陷与测试重点 |
| :--- | :--- | :--- | :--- |
| **Path 1** | **严谨推导者** | 第一性原理数学与逻辑证明 | 给出完整推导步骤、中间量、收敛过程与公式解析 |
| **Path 2** | **红队对抗者** | 假设方案存在致命漏洞的攻防者 | 极值边界、浮点截断、除零异常、时区夏令时错位、负数穿仓 |
| **Path 3** | **极简执行者** | 最小可用代码践行者 (YAGNI) | 编写可跑测试脚本并在独立临时沙箱中执行，持有 Pass@k 一票否决权 |

## 四、关键防线：递归阻断与深度限制

子代理在 DeepSeek Harness 中会继承父会话的预设配置。若不加防御，子代理遇到高危任务将继续裂变为孙代理，引发指数级上下文爆炸与资源耗尽。
- **深度硬性限制**: 配置 `maxDepth: 1`，引擎层调用 `resolveChildDepth()` 时直接抛出 `SubagentDepthError` 阻断孙代理派生；
- **Persona 角色覆盖**: 子代理注入专属执行者 Persona，剥离父会话特权，禁止其输出 `[JEV: ...]` 裁决头；
- **角色互斥锁**: 派发前校验三角色唯一性，彻底杜绝多发或重发缺陷。

## 五、上下文修剪与长对话注意力保护 (Compaction Pipeline)

```
[原始超大工具输出] 
       │ (> 8192 字符)
       ▼
┌──────────────────────────────────────────────┐
│  Head (前 4096 字符): 输入参数 / 初始化配置  │
├──────────────────────────────────────────────┤
│  [... 中间长日志与冗余输出自适应修剪 ...]    │
├──────────────────────────────────────────────┤
│  Tail (后 1024 字符): 关键代码与断言执行结果 │
└──────────────────────────────────────────────┘
```
通过头部与尾部双锚点保留策略，既保证核心证据链完整，又将长程运行 5 小时以上的会话 Token 消耗降低 60% 以上。
