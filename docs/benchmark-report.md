# JEV 极端边界压力测试基准分析报告 (Benchmark Analysis Report)

## 一、评测概述与背景
在量化交易系统开发与算法模型推导中，精度陷阱、边界条件突变以及时区/日历错位往往造成灾难性的实际资金穿仓。
本基准测试矩阵共设计 **30 个高危量化计算与精度陷阱任务**（覆盖 5 大核心风险域），通过 JEV 自适应交叉验证模式进行全方位极限压测：
1. **Tick 大小截断与浮点精度丢失 (CASE-01 ~ CASE-06)**
2. **阶梯维持保证金与强平穿仓推导 (CASE-07 ~ CASE-12)**
3. **双边滑点与非线性市场冲击预算穿透 (CASE-13 ~ CASE-18)**
4. **跨国时区对齐与夏令时跳跃 (CASE-19 ~ CASE-24)**
5. **复权因子除零与精度坍塌 (CASE-25 ~ CASE-30)**

## 三、沙箱执行 (Pass@k) 一票否决权实证案例

在 CASE-02 (期权向上截断防零报价) 与 CASE-12 (资金费率动态侵蚀) 的首次沙箱运行中，Path 3 生成的代码在直接拼接 JSON 布尔值时使用了小写 `true/false` 而非 Python 原生布尔或解析器，导致 Python 解释器直接抛出 `NameError: name 'true' is not defined`。

- **传统单模型直接输出**: 模型在文本层面对自己的逻辑表现出高度自洽与过度自信（"格式正确，已仔细检查"），如果无沙箱拦截，带有语法缺陷或类型冲突的代码将直接进入生产环境。
- **JEV 一票否决机制介入**: 沙箱执行直接返回 `exit status 1`，立即熔断！强制修正为严密的 `json.loads` 反序列化与严格类型断言，直至代码完全绿灯。

## 四、五大高危风险域典型陷阱剖析

### 1. Tick 大小强制向上/向下截断 (Tick Size Truncation)
- **陷阱**: 浮点数表示（如 `67432.178`）在 IEEE 754 底层为 `67432.177999999997...`。若采用简单除法后 `int()` 截断，极易多截断一个最小单位；若使用四舍五入，限价买单价格高于原始预算直接触发交易所拒单或逆向穿透。
- **JEV 防御**: Path 1 强制使用 `Decimal` 并指定 `ROUND_FLOOR` 或 `ROUND_CEILING`；Path 2 红队构造 `0.00000001` 等极限 tick 步长进行边界探测。

### 2. 阶梯保证金与速算扣除数 (Tiered Margin & Liquidation)
- **陷阱**: 计算多档维持保证金（MMR）时，许多模型错误地使用当前持仓所在最高档位 MMR 直接乘以总名义价值，忽略了前面档位优惠带来的「速算扣除数 (Quick Deduction)」，导致维持保证金被大幅高估 30%~50%，过早误判强平。
- **JEV 防御**: Path 1 分段积分推导速算扣除数公式；Path 2 针对反向币本位合约建立双曲线方程 $P_{liq} = \frac{Contracts \times Face \times (1 + MMR)}{Balance + \frac{Contracts \times Face}{Entry}}$，彻底杜绝正反向合约混淆。

### 3. 双边滑点与非线性冲击预算穿透 (Slippage Penetration)
- **陷阱**: 在市价大单吃单与 AMM 恒定乘积池交易中，许多策略仅考虑线性报价差，忽视订单簿深度耗尽与 $k = x \cdot y$ 的非线性滑点以及双边手续费垫资，导致开仓即遭遇 `INSUFFICIENT_MARGIN`。
- **JEV 防御**: Path 1 严格计算 VWAP 与 Almgren-Chriss 平方根冲击模型，明确计算超支基点 (Overrun bps)；Path 3 真实断言最大安全可开仓名义价值。

### 4. 时区夏令时错位 (Timezone & DST Shift)
- **陷阱**: 美股与欧股在每年 3 月夏令时切换日存在 2~3 周的「时差窗口错位」（纽约已进入 EDT UTC-4，而伦敦仍在 GMT UTC+0，时差由 5 小时突变为 4 小时）。此外，3 月切换日当天当地仅有 23 小时，11 月切换日有 25 小时，写死 `assert len(bars) == 24` 的日 K 线合成逻辑直接崩溃。
- **JEV 防御**: Path 1 引入 IANA 规范化时区感知对象；Path 2 注入 `AmbiguousTimeError` 与时钟回拨 (-1 ns) 对抗测试用例。

### 5. 复权因子除零与精度坍塌 (Adjustment Factor Zero-Division)
- **陷阱**: 巨额高送转（如 10 送转 30 股派 3 元）若使用定额前复权，历史股价将变为负数，导致后续计算对数收益率 $\ln(P_t / P_{t-1})$ 时触发数学定义域错误 (`math domain error`)；缩股（Reverse Split）时未将成交量按倒数调整导致量化异动警报误触发。
- **JEV 防御**: Path 1 确立乘法前复权因子守恒律；Path 2 攻击除零与极小股息 50 年复利下溢。

> 以下"语义分歧边界"内容保留作为**待验证的假设清单**，并非实测结论：
**潜在语义分歧边界条件总结**：
1. **金融舍入标准的定义域分歧**：在四舍五入中，部分交易所采用 `ROUND_HALF_UP`（如传统现货），部分采用银行家舍入 `ROUND_HALF_EVEN`（如高频结算）。若 Prompt 未明确约束舍入法则，Path 1 与 Path 3 可能在 `*.005` 临界点产生 1 个 tick 的数值差异。
2. **极端流动性枯竭断言**：当订单簿卖盘总量无法满足买单需求时，是返回部分成交（Partial Fill），还是整单撤销（Reject）。JEV 模式必须在 Prompt 中显式声明订单执行类型（IOC、FOK 还是 GTC）。
